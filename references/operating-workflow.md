# 运行工作流

在制定每日任务、开放盲测、批改、纠正、验证或评估风险时读取本文件。具体数量、科目覆盖和得分规则以考试配置为准。

## 1. 预检

1. 读取考试配置与权威状态源，确定当前阶段、剩余天数、可用时间和未完成队列。
2. 检查首次成绩是否被覆盖、同一题是否跨角色复用、封存题是否泄漏、状态升级是否缺少证据。
3. 优先处理会阻止继续推进的冲突。已有纠正队列按配置决定是否必须先清零，但不得把未纠正状态静默改成完成。
4. 依据分值权重、未覆盖范围、近期盲测表现和验证到期项分配当天预算；不要因为资料未读完突破时间上限。

## 2. 教学阶段

1. 从允许使用的资料、已解封题目和候选教学题中确定当天原子知识点集合。
2. 合并同义或重复材料，为知识点分配稳定 ID，并保留唯一主版本与来源指针。
3. 使用 A 类教学题支持理解。A 类答案可以即时反馈，但其成绩单独保存，不进入正式完成分。
4. 完成并冻结教学正文。冻结前不得读取当天正式 B 类候选题的题干、选项、答案或解析。

## 3. 盲测阶段

1. 冻结教学后，选取同知识范围的其他真实题、陌生题或可靠变式题；不得与 A 类复用同一道题。
2. 生成只含题目和作答说明的独立 B 类题卷。答案与解析放在用户无法在首次提交前看到的独立载体中，或在提交后才生成。
3. 用户提交后立即保存原始提交内容、提交时间、题卷版本和作答条件，再开始评分。
4. 单科、总分、题型分项及错选/少选/遗漏等按配置记录。任何不确定评分规则先标记待核验，不擅自计分。

## 4. 纠正与状态迁移

默认状态语义：

```text
未学习 → 已学习
已学习 + B首次正确 → 已掌握候选
已学习 + B首次错误 + 当天订正正确 → 已纠正
已掌握候选/已纠正 + 后续陌生题通过 → 已掌握
已掌握 + 后续混合题或变式题通过 → 已稳定
```

- 纠正需要重新作答或给出关键推理，不以“阅读了解析”代替。
- 验证失败时保留失败证据并降级或重新排程；不得仅延后日期而保持虚假的高状态。
- 时间不足时优先保留高权重、近期失败和高风险易混项；低风险验证可以延后，但必须记录。
- 闪卡复习、重复原题正确或紧接解析后的回答不构成陌生题证据。

## 5. 完成判定与回写

1. 使用配置中的日门槛判断；不得用 A 类成绩或补测成绩填补 B 类首次得分。
2. “纠正队列清零”只说明当日错误已处理，不自动升级掌握状态。
3. 先保存题目映射、首次提交、逐题评分和纠正证据，再更新汇总成绩、滚动表现与完成日期。
4. 输出生成但用户尚未作答时，只登记“已推送待完成”。
5. 若启用记忆适配器，只在首次提交锁定并完成批改、错误和不稳定项已记录后调用；实际导入或外部同步仍受用户授权和适配器自身规则约束。

## 6. 阶段与风险评估

- 基础阶段：优先建立高权重知识框架和稳定 ID，不追求逐本读完重复资料。
- 强化阶段：以未使用题目和混合迁移为主，使用错题反向修补知识缺口。
- 最终阶段：解封保留卷，执行首次、闭卷、限时整卷测试；原始分永久保存。
- 风险报告至少给出正式合格线、训练目标、首次成绩、安全边际、样本量和作答条件。只有符合配置要求的封存整卷能作为最强预测证据。

## 7. 失败停止条件

遇到以下情况停止进入下一运行门，并说明恢复条件：

- 状态源不可读或出现相互矛盾的权威记录；
- 首次提交已被覆盖且无法恢复；
- A/B 题复用或正式答案提前泄漏；
- 封存卷在解封前被读取；
- 评分规则或时效性规则无法可靠确认；
- 输出写入或首次提交持久化失败。
